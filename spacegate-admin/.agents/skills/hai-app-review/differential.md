# 差异审查

应用改动自查、PR/提交/分支审查按需读取。本方法借鉴 [Trail of Bits differential-review](https://github.com/trailofbits/skills/tree/main/plugins/differential-review)，按实际风险选择审查深度，不以 diff 行数决定安全性。

## 1. 固定比较对象

PR 使用其实际 base/head SHA，分支使用已确认集成分支与目标分支的 merge-base。记录比较命令和两端 SHA；区分提交间差异、staged、unstaged 和未跟踪文件。审查期间 head 变化时，补审新增差异并重新核验受影响结论，不沿用旧行号声称已审查当前版本。

先列 `git diff --name-status --find-renames <base> <head>`、统计和完整 diff，再按需读取文件上下文、公开类型、测试、配置及调用方。不能仅凭截断 diff 做全量结论。无 Git、远程权限不足或缺少 base 时，说明实际可读范围，继续可进行的文件级审查。

## 2. 先找可能造成较大后果的变化

| 变化 | 必查内容 |
| --- | --- |
| 登录、鉴权、租户、资源 ID、输入校验 | 谁能调用、能操作谁的数据、校验移除后替代约束是否真实存在 |
| 支付、上传、外部请求、AI 工具、任务 | 验签、目的地/大小限制、幂等、未知结果、重试/取消和外部副作用 |
| 状态、事务、迁移、共享缓存 | 并发/跨节点约束、失败回滚、存量数据和兼容调用方 |
| 公共 API、配置、默认值、导出、模板 | 正反向调用、公开类型、目标平台和生成应用是否同步 |
| UI 和内容渲染 | 服务端权限、HTML/URL 边界、交互丢失、键盘、焦点和语言；不能自动判为低风险 |
| CI、依赖、部署脚本 | 按 [hai-ci](../hai-ci/SKILL.md) 核对执行来源、权限、密钥与发布条件 |

对高风险符号用 `rg` 查直接调用方及关键间接路径，列出实际依赖范围；动态注册、远端消费者无法确定时说明限制，引用数量不代表完整影响。对删除的校验、锁、事务和失败处理读相关 `git log` / `git blame`，判断是否移除了此前修复的约束。没有替代实现的“只是重构”仍需验证行为。

## 3. 两次核对

第一次核对需求符合性：逐条检查当前目标验收，区分完整实现、已有满足、未实现和证据不足。第二次沿输入 → 身份/资源 → 服务/副作用 → 结果 → UI 检查正确性与集成。只读当前风险需要的模块资料，普通改动不升级为无关的全面安全审计。

把可疑点转为具体场景，例如“普通用户提交其他租户的资源 ID，更新语句未包含租户条件”，再核对上游守卫、服务和数据库约束能否实际阻止它。验证新/改变行为对应的成功与失败用例；缺少测试表示验证缺口，不直接证明漏洞，也不能仅因此提高业务问题严重程度。

## 4. 报告与复核

采用 [交接契约](../hai-spec-implement/handoff.md) 的发现格式。每条引用当前差异行及必要上下文，说明改动引入还是既有问题、触发条件、具体后果、证据充分程度、最小修正和验证方式。排除不成立的线索，不将已否定建议继续列为风险。

结尾记录已覆盖文件/路径、未读或被截断部分、未执行验证和原因、需要交付前解决的事项。无发现只说明本次范围未确认问题，不等同于全系统无缺陷或 CI 已通过。
