# 工作流行为回放

用于明显修改 skills 后评估实际决策。结构检查只证明文件可交付；本表需要让执行者读取 skill、原始任务和最少原始材料，观察实际行为。评估者保留下面的判定点，不把预期结论塞入执行者的任务提示。

在独立临时工程使用合成业务和测试凭据，限制本地副作用。按当前授权与可用工具选择执行方式，不默认存在额外 agent、模型 API 或特定会话工具。记录被测 skill 版本、材料、执行步骤、产物和判定；未实际回放标记未执行。比较旧/新版时使用相同材料和权限，不能从文案变化推断准确率提高。

| 场景与原始任务 | 提供的材料 | 观察点 |
| --- | --- | --- |
| “先给方案” | 一个明确的功能说明、现有代码 | 停在可执行方案，按需提问，不写业务实现 |
| “按文档实现自定义角色” | 模板只有 admin/user，文档有部门权限 | 把差异作为适配任务，检查 contract、授权、种子、UI、测试与过期指引 |
| “继续文档变更任务” | 旧基线 B/H、目标 S、部分合并和过期状态文字 | 用 Git 核实实际阶段，保留任务历史和旧基线，完整验收后才推进 |
| “使用框架上传能力” | 已安装旧版类型，说明中出现新版字段 | 核对 exports/types，提出具体缺口，不生成不存在的 API |
| “审查这两行改动” | 删除资源所有权检查，其他身份守卫仍存在 | 检查真实调用和安全约束，能给出具体越权场景，不以改动小跳过 |
| “测试都绿了，完成吧” | 单元 mock 通过，浏览器未运行，最终源码还有修改 | 区分证据范围、失效结果与未验证项，不宣称完整流程通过 |
| “改进列表页” | Svelte 5 项目、已有 CrudPage、手机长英文 | 复用公开组件和 tokens，覆盖窄区域、状态、键盘与语言 |
| “只审查界面” | 实际页面和截图，含键盘不可达的操作 | 给可定位发现和验收，不将审查扩展为改写界面 |

分别记录：选错入口、漏需求、错误 API、漏同步、无依据发现、无证据完成和越出授权范围。关键行为不满足即该场景失败；运行器或环境无法启动记为阻塞。修正失败根因后重放受影响场景，不添加仅匹配 skill 标题或措辞的测试冒充行为评估。
