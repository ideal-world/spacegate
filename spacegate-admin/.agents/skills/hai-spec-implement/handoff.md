# 工作交接与完成证据

SDD 的规划、实现、测试、应用审查和 PR 审查共享本契约。已有任务清单和项目文档是记录入口；小改动可在交付说明中记录，不要求另建计划、JSON 状态文件或调度系统。

## 选择路径

| 请求 | 处理路径 | 结束条件 |
| --- | --- | --- |
| 分析、方案、文档审查 | hai-spec-review；需要拆分时进入 hai-spec-implement 的规划路径 | 给出问题、选择或可执行计划，保持分析范围 |
| 已明确的小功能、缺陷修复 | hai-app-create → hai-app-tests → hai-app-review | 本次行为与受影响回归验证完成 |
| 按文档实施、继续、返修或同步变更 | hai-spec-review → hai-spec-implement；任务内调用 hai-app-create、hai-app-tests、hai-app-review | 按用户指定交付方式完成任务和整体验收，随后推进基线 |
| 页面设计或明显改变布局、信息结构 | hai-ui-design → hai-ui；实现仍由 hai-app-create 编排 | 设计规则映射到当前版本组件与界面验收 |
| 界面审查 | hai-ui-review；跨层业务再进入 hai-app-review | 界面问题有真实页面、触发操作和证据 |
| PR、提交或分支审查 | hai-pr-review，代码规则复用 hai-app-review | 对固定差异给出可复核发现与交付条件 |

先复用已确认的需求和设计；只澄清会改变业务行为、范围或授权且无法从现有材料确认的问题。已有实施授权持续有效，阶段转换和普通实现细节不重复请求批准。默认串行，子代理或新会话依实际用户/项目授权与工具可用性决定，不能把其存在作为工作前提。

## 各阶段传递什么

| 信息 | 最少内容 | 维护位置 |
| --- | --- | --- |
| 目标 | 用户目标、范围、明确不做项、需求版本和权威关系 | 已有需求/任务概要 |
| 验收 | 角色、输入和操作 → 可观察结果；适用的失败与权限边界 | 复用需求编号；缺少时增加稳定的验收编号 |
| 复用 | 应用现有能力、框架安装版本、公开 exports/types、配置/平台限制和真实缺口 | 任务的复用与影响部分 |
| 执行 | 当前步骤、依赖、实际分支/提交、未完成项与恢复条件 | 任务记录或本次交付说明 |
| 发现 | 编号、优先级、位置、触发条件、后果、证据、建议和验收 | 原问题清单，修复后原地追加结论 |
| 证据 | 验收编号、被测源码、命令/操作、环境、结果、日志/截图位置 | 任务的本轮证据；大文件留在忽略目录 |

一条验收可以由多层证据共同支持；一条用例也可验证多个验收。不要用一一对应的文件数量强迫拆分。需求已满足时记录现有实现和运行证据，避免重新实现。

## 发现如何确认

- P0：严重安全、数据损坏或核心业务不可用；P1：关键规则、流程或权限错误；P2：局部行为、可访问性或维护问题；可选审美/风格建议单列。
- 确认发现须有代码、文档、复现或确定的契约依据。写出实际触发条件和后果，合并同一根因的重复发现。尚缺关键证据的线索标记待核实，不能靠多个审查者重复提出而升级为确定缺陷。
- 修复后记录实现位置、验证结果和剩余边界。既有修复授权覆盖本次范围内的发现；范围外问题记录后续事项。只读审查只交付发现。

## 证据有效性与收尾

测试记录至少能回答“测的是哪些代码、什么环境、什么行为、结果是什么”。Git 项目记录提交及未提交差异摘要；同一提交下存在未提交修改时不能只记录 SHA。无 Git 时记录可重现的文件快照标识和限制。

代码、配置、依赖或环境变化后，重跑受影响项；未变化且依赖条件相同的结果可依 [分轮规范](../hai-app-tests/validation.md) 复用。完整门禁需要实际结束和退出码；超时、中断、未执行、环境阻塞各自记录。静态检查、mock、容器、浏览器、真实 Provider 和原生平台提供不同证据，不互相替代。

收尾逐项核对验收和同步范围：contract/schema、服务端权限、数据迁移/种子、配置、调用方、UI/i18n、测试、README、skills 和目标端。每项完成、排除或阻塞均有理由。任务状态与实际代码/合并/验证一致；文档基线只按 [changes.md](changes.md) 推进。

## 保留什么经验

先把可机器验证的约束写成测试或类型，把局部非显然原因写入注释。只有跨边界、持久且重复调查成本高的经验才补入项目已有知识文档，包含症状、根因、已验证方案、适用版本/平台、来源和失效条件。规划下一次相关工作时检索这些材料，并以当前实现复核。普通改动历史放在任务或提交说明，未验证猜测保持为线索。
