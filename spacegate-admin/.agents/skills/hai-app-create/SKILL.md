# hai-app-create

## 能力契约

| 项目 | 契约 |
| --- | --- |
| 能力 | 在 hai 应用中新增、修改或修复页面、API、服务、模型与组件 |
| 适用场景 | 日常应用功能开发与已授权修复 |
| 输入 | 功能需求、现有路由/contract、数据模型和验收场景 |
| 输出 | 能力选择依据、最小实现、行为验证、i18n 与受影响文档 |
| 限制 | 优先复用；TDD 验证本次目标行为，仍适用的回归保持通过。保留 API workspace 架构时不混入 SvelteKit 路由。 |

## 使用路径

范围、验收、复用依据和证据按 [工作交接契约](../hai-spec-implement/handoff.md) 贯穿实现、测试和审查；小改动使用简短记录，文档驱动任务沿既有任务记录续跑。

业务以用户当前明确要求及其指定文档为准；模板规则、生成代码与测试只描述初始方案。需求改变角色、流程、限额或架构时，在已有授权范围内同步调整冲突实现及过期 AGENTS/skills/README，不要求把需求改回模板。具体判定见 [development.md](development.md#需求与模板的关系)。

从需求/设计文档开始生成项目或功能前，使用 [hai-spec-review](../hai-spec-review/SKILL.md) 检查文档是否足以确定实现；修正影响行为的缺项、歧义和技术错误后再进入生成。普通小改动按本次范围确认规则，不要求重审无关文档。

需要按文档规划/执行、返修或根据已提交文档差异同步实现时，使用 [hai-spec-implement](../hai-spec-implement/SKILL.md) 管理 docs 清单、任务记录、文档基线、TDD 和任务分支；本 skill 负责其中的具体应用实现，复用固定目标版本、范围与验收。

需要新建项目、添加模块、补齐配置或生成代码时，先按 [CLI 安装与命令](development.md#cli-安装与命令) 全局安装 `@h-ai/cli`，再执行 `hai` 命令。

1. 读取 [development.md](development.md)：先按真实需求匹配框架能力、已安装版本与应用架构，再确定改动。适用能力包括同一模块已有 feature、配置和扩展点，不以导入包作为复用完成的证据。
2. 读取所选模块的 skill 与实际公开类型，复用现有服务和组件。新增依赖或直接使用第三方 SDK 前说明已有能力的具体缺口；无需安装无关模块。
3. 新增或改变行为时用有意义的目标用例验证，仍适用的回归保持通过；被明确新需求替代的模板断言同步更新并记录依据。按下方参考实现，使用 [hai-app-review](../hai-app-review/SKILL.md) 检查改动涉及的安全与质量边界。
4. 按 [分轮验证与集中修复](../hai-app-tests/validation.md) 运行已有门禁：一轮先收集所有可执行结果，再归并修复、复测失败及受影响项；报告行为证据、能力选择及未验证项。纯文案、格式和文档变化按影响验证，不强制新增测试。

## 按需参考

界面新建或明显改变信息结构时先用已交付的 hai-ui-design 确定页面模式、状态和组件映射；使用 hai-ui 的当前版本契约实现，以 hai-ui-review 的真实页面检查收尾。窄范围修复直接复用既有设计。界面方案与最终实现的差异需回写适用设计记录。

新增新手引导或帮助说明时读取 [UI 引导指南](../hai-ui/guide.md)，复用 fullstack 默认的共享 guide-store、locale 和稳定 data-guide 锚点。

按任务读取 [reference.md](reference.md) 的对应小节；签名以当前源码或安装版本的公开类型为准，不默认加载全部资料。示例中的业务变量由应用提供。
