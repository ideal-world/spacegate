# hai-ui-review

## 能力契约

| 项目 | 契约 |
| --- | --- |
| 能力 | 根据用户任务与真实渲染检查界面体验和技术质量 |
| 适用场景 | 界面走查、前端改动自查、布局/交互评审与已授权修复验收 |
| 输入 | 目标页面/组件、需求或设计约定、运行环境、实际界面与相关实现 |
| 输出 | 带位置、操作、后果和截图/运行证据的问题清单及复测结果 |
| 限制 | 只读请求不自动修改；审美偏好单列，不能推翻明确设计。浏览器证据不等于原生平台或真实外部服务验收。 |

## 审查路径

1. 明确本次页面、角色、主要任务、设计约定与授权范围；理解本次是局部改善还是重新设计。沿 [hai-ui-design](../hai-ui-design/SKILL.md) 的页面任务判断层级、密度和表达。
2. 使用项目已有运行/浏览器测试入口装配隔离环境。先看真实页面再定位源码；不能启动时做源码/已有截图审查，标明截图来源与新旧关系，记录实际浏览器未验证。
3. 按 [走查清单](checklist.md) 完成用户路径。先处理任务无法完成、状态错误、键盘不可达和内容溢出，再评估布局一致性、层级和细节。每个问题记录具体页面、尺寸、语言/主题、操作和实际后果。
4. 复核发现是否来自公共组件、业务组合、设计规则或环境。公共问题优先修正 [hai-ui](../hai-ui/SKILL.md) 对应组件，再同步应用、CLI、文档；业务专属问题留在业务层，实际权限仍由服务端验收。
5. 已授权修复时集中处理本轮发现，再批量复测受影响路径和尺寸；需要行为回归时按 [hai-app-tests](../hai-app-tests/SKILL.md) 选合适测试层。纯视觉调整使用真实渲染验证，避免只匹配 class 字符串的测试。

## 问题与证据

沿 [交接契约](../hai-spec-implement/handoff.md) 记录稳定编号、优先级、位置、触发操作、后果、依据、建议和验收。截图证明布局，浏览器操作证明交互，服务/存储证据证明业务效果；三者按实际范围分别说明。

先报告已确认问题，再列实际覆盖和未验证边界。已修复项附本轮源码标识、操作与结果，日志/截图放 Git 忽略目录。没有浏览器或宿主环境时继续能做的检查，保留环境限制，不将静态清单视为实际通过。
