# hai-app-tests

## 能力契约

| 项目 | 契约 |
| --- | --- |
| 能力 | 编写或修复 Vitest/Playwright 测试，组织质量门禁与业务流程的分轮验证 |
| 适用场景 | 需求验收、缺陷回归或应用测试改进 |
| 输入 | 验收条件、被测公共入口、现有测试和运行环境 |
| 输出 | 可复现用例及明确区分静态、mock、浏览器/外部服务的结果 |
| 限制 | Red 阶段验证本次目标用例因行为缺失而失败，不要求无关回归失败；不能为迁就实现删除断言或修改预期。 |

## 使用路径

先复用 [工作交接契约](../hai-spec-implement/handoff.md) 中的验收编号和本轮范围。结果关联提交与未提交差异、命令/操作、依赖与环境、退出码和证据位置；源码/配置/依赖或环境变化后按影响使旧结果失效并复测。测试通过只是相应验收的证据，整体验收仍逐项核对需求。

- 先选单元/集成/浏览器层，复用测试 fixture，验证用户可观察结果。
- 验收以用户当前明确要求和指定业务文档为准；模板测试不是不可变需求。规则已改变时同步更新或替换过期断言，记录新需求依据并覆盖新的授权/失败边界；保留仍适用的回归，不能用“保持旧测试通过”强留冲突业务。
- 按 [development.md](../hai-app-create/development.md) 的真实行为与安全边界选测试；新增/改变业务行为、缺陷修复有目标用例，纯文案/格式/文档及无行为变化的可逆低影响修改不补镜像测试。
- 不要求每个功能同时新增单元与 E2E；复用已有用例，选择能验证变化的最小适用层，关键跨层用户流程仍需端到端证据。
- 新用例已通过时先检查是否已有能力；不能为达成 Red 人为破坏旧测试。
- 执行多项门禁前读取 [分轮验证与集中修复](validation.md)：一轮先脚本化收集所有可执行检查及日志，普通失败不立即改代码；汇总去重后集中修复，先定向复测失败、解除阻塞和直接受影响项，全部通过后再扩大验收。定向回归未通过时不重跑整套门禁。只有真实前置阻塞才暂停依赖检查；最终必需门禁均须对最终代码有效通过。小范围 TDD Red → Green 保留。
- 外部服务未运行必须报告；mock/Testcontainers/浏览器/真实付费 Provider 的结果分开表述。
